# Codex Studio — план реализации

> Для исполнителя: выполнять последовательно через superpowers:executing-plans. Реализация в этом запросе не начинается.

**Цель:** публичный плагин Android Studio для работы с локальным Codex через интерфейс чата.
**Архитектура:** Kotlin-плагин управляет Codex App Server по stdio JSON-RPC. React-интерфейс работает внутри одной JCEF-панели и обменивается типизированными сообщениями с Kotlin. Собственный сервер и прямые вызовы OpenAI API не нужны.
**Стек:** Kotlin, IntelliJ Platform SDK, Gradle Kotlin DSL, Coroutines, kotlinx.serialization; React, TypeScript, Vite, JCEF.
**Спецификация:** требования пользователя и принятые решения зафиксированы ниже. Рабочее название Codex Studio; публичное название выбрать перед публикацией.

## Требования и ограничения

- Только Codex и доступные через него модели OpenAI; другие агенты и провайдеры исключены.
- Панель открывается кнопкой справа; интерфейс напоминает веб-чат и учитывает тему IDE.
- Enter отправляет сообщение; Shift+Enter добавляет новую строку. При открытом меню Enter сначала выбирает пункт; во время IME-композиции не отправляет сообщение.
- Потоковый ответ, Markdown, код с копированием, карточки выполняемых действий, остановка запроса.
- Выбор модели и поддерживаемого уровня reasoning; список берётся у Codex, названия не зашиваются в интерфейс.
- Файлы: кнопка, drag-and-drop, @ с поиском файлов проекта. Изображения: кнопка, drag-and-drop, вставка из буфера, предпросмотр и удаление.
- Slash-меню с описаниями; команды интерфейса маршрутизируются явно, а не отправляются как обычный текст модели.
- Поддерживаемые Codex skills, плагины и MCP доступны в рамках возможностей установленной версии; произвольные расширения ChatGPT не переносятся автоматически.
- Именованные вкладки, новый чат, несколько независимых разговоров, история и поиск, восстановление после перезапуска IDE.
- В каждой сессии показываются рабочая директория, текущая ветка и заполненность контекста.
- При заполненности строго больше 70% индикатор оранжевый и предлагается /compact. При 90% и выше — красный. Ровно 70% не вызывает предупреждение.
- /compact запускает штатное сжатие Codex. /concat — исправленная опечатка, отдельной командой не вводится.
- Без режима обучения, отдельного окна diff, кнопок принятия/отката патчей и специальных функций Logcat, эмулятора или Gradle.
- Агент сохраняет обычную возможность читать/менять файлы и запускать команды. Отсутствие diff не отключает изменения файлов.
- Никакой полной индексации или автоматической отправки всего проекта при запуске плагина.

## Принятые решения

1. Одна JCEF-панель на проект, вкладки переключают её состояние. Один App Server на открытый проект, несколько thread внутри него. Запуск ленивый, после открытия панели.
2. Codex установлен отдельно. Первый запуск обнаруживает бинарник, проверяет версию и вход; путь можно указать вручную. Установка и обновление CLI без ведома пользователя не выполняются.
3. Использовать существующую авторизацию Codex и поддерживаемый им вход; пароли и токены не помещать в webview или настройки проекта. Для секретов, если понадобятся, использовать PasswordSafe.
4. Совместимость: на первом этапе зафиксировать фактический build целевой Android Studio и проверенную версию Codex. Минимальные версии определяются проверкой протокола, не догадкой. macOS ARM64 — первая проверяемая платформа; Windows/Linux — отдельная проверка до объявления поддержки.
5. Источник истории — Codex. Локально хранить только метаданные интерфейса, черновики и вложения, не создавать независимую дублирующую историю. Метаданные — PersistentStateComponent, бинарные вложения — в каталоге данных плагина вне репозитория.
6. Закрытие вкладки не удаляет разговор. Архивация явная; активный запрос при закрытии вкладки продолжает работать и виден в списке задач. При закрытии проекта корректно освобождать процессы и ресурсы.
7. До двух одновременных запросов на проект по умолчанию; остальные в очереди. Предупреждать, что чаты в одной директории работают с одними файлами. Worktree и управление ветками не входят в первую версию.
8. Текущую ветку определять по реальному Git-корню рабочей директории сессии, обновлять после смены ветки и при фокусе. Поддержать detached HEAD, несколько Git-корней и отсутствие Git. Ветка не закрепляется за чатом автоматически.
9. Контекст считать по данным последнего актуального использования и размеру окна из протокола, не по сумме расхода токенов за всю историю. Формулу сверить со схемой закреплённой версии и поведением Codex. При отсутствии данных показывать «Нет данных», при устаревших — пометку. Не подменять неизвестное значение нулём.
10. 70% — порог предупреждения интерфейса, а не обещание порога автоматического сжатия Codex. После ручного или автоматического сжатия обновить индикатор по событию. Во время запроса ручное сжатие недоступно; не ставить его скрыто в очередь.
11. Смена модели применяется со следующего запроса и не создаёт новый чат. При уменьшении окна пересчитать индикатор и обработать требование сжатия со стороны Codex.
12. Разрешения и sandbox сохраняются; запросы одобрения показываются внутри нужной сессии. Плагин не включает обход разрешений.
13. Markdown не исполняет HTML/JS. Мост webview принимает только разрешённые типы сообщений. Бинарник запускается массивом аргументов, без сборки shell-строк.
14. Вложения хранят стабильную копию до отправки. Текстовые файлы, пути и изображения передаются средствами поддерживаемого протокола. Не обещать обработку произвольных PDF/архивов как текста. Несохранённый редактор предлагается сохранить перед прикреплением.
15. Команды /new, /model, /status, /compact, /resume реализуются на уровне GUI с соответствующими вызовами. Skills и прочие команды подключаются по проверенным возможностям Codex. Для неподдерживаемых терминальных команд показывать объяснение, не имитировать успех.

## Состав интерфейса

- Сверху: вкладки разговоров, переименование, кнопка «+», история, настройки.
- Центр: сообщения, Markdown и код, сворачиваемые карточки команд и действий, запросы разрешений.
- Под сообщениями: предупреждение о контексте, когда оно актуально.
- Снизу: многострочный ввод, вложения, @, /, модель, reasoning, отправка/остановка.
- Строка состояния: ветка, рабочая директория, процент занятого контекста и статус агента.

## Структура файлов

- src/main/kotlin/.../toolwindow/CodexToolWindowFactory.kt — панель и жизненный цикл JCEF.
- src/main/kotlin/.../bridge/UiBridge.kt — проверяемые сообщения webview ↔ Kotlin.
- src/main/kotlin/.../codex/CodexProcess.kt — запуск, stdio, завершение.
- src/main/kotlin/.../codex/JsonRpcClient.kt — запросы, ответы, серверные запросы, таймауты.
- src/main/kotlin/.../codex/CodexProtocol.kt — DTO закреплённой версии протокола.
- src/main/kotlin/.../sessions/SessionService.kt — thread, turns, очередь, восстановление.
- src/main/kotlin/.../sessions/SessionUiState.kt — черновики, вкладки, локальные имена при необходимости.
- src/main/kotlin/.../context/ContextUsageService.kt — заполненность, актуальность, предупреждение.
- src/main/kotlin/.../git/BranchService.kt — Git-корень и текущая ветка.
- src/main/kotlin/.../attachments/AttachmentService.kt — файлы, изображения, время жизни копий.
- src/main/kotlin/.../commands/CommandRegistry.kt — slash-команды и доступность расширений.
- src/main/resources/META-INF/plugin.xml — регистрация плагина, tool window, зависимости.
- webview/src/ — App, ChatTabs, MessageList, Composer, ModelSelector, ContextIndicator, StatusBar.
- src/test/ и webview/src/**/*.test.ts(x) — значимые проверки протокола, состояния и ввода.

## Этапы реализации

### 1. Проверить протокол и собрать рабочий каркас
- [ ] Зафиксировать Android Studio build, JDK/Gradle и версию Codex; проверить наличие JCEF.
- [ ] Снять схемы App Server и составить таблицу возможностей: вход, модели, threads, usage, compact, skills/plugins.
- [ ] Создать Kotlin-плагин и минимальную JCEF-панель с локально собранным webview.
- [ ] Проверка: runIde открывает панель; закрытие проекта освобождает JCEF. При неподдерживаемой версии показывается понятное сообщение.

### 2. Подключить Codex
- [ ] Проверки JsonRpcClient: фрагментированный JSONL, несколько строк за чтение, неверный JSON, неизвестное событие, error response и завершение процесса.
- [ ] Реализовать запуск, initialize, чтение моделей, создание thread, отправку turn, получение событий и interrupt.
- [ ] Реализовать обнаружение CLI, ручной путь и поддерживаемую авторизацию.
- [ ] Проверка: реальный запрос получает потоковый ответ; Stop останавливает задачу; повторное подключение не дублирует turn и не отправляет запрос автоматически повторно.

### 3. Сделать чат и ввод
- [ ] Реализовать сообщения, Markdown, копирование кода, карточки действий и разрешений.
- [ ] Реализовать Enter/Shift+Enter, черновик, отправку, остановку и выбор модели/reasoning.
- [ ] Проверки ввода: перенос строки, многострочная вставка, IME, открытое меню, пустой запрос, двойной Enter; исключить двойную отправку.
- [ ] Проверка: длинный ответ не блокирует ввод; поток обновляется пакетами, список виртуализирован.

### 4. Добавить вложения и команды
- [ ] Реализовать кнопку вложений, drag-and-drop, буфер изображений, миниатюры и удаление.
- [ ] Реализовать @ по файлам проекта с исключением служебных каталогов и отменой устаревшего поиска.
- [ ] Реализовать slash-меню и явную маршрутизацию GUI-команд, skills и доступных расширений Codex.
- [ ] Проверки: пробелы/кириллица в пути, удалённый файл, большое/неподдерживаемое вложение, отправка только изображения, недоступный skill. Проверить реальное получение изображения агентом.

### 5. Добавить сессии и историю
- [ ] Реализовать вкладки, названия, новый чат, поиск истории, resume и архив.
- [ ] Сохранять соответствие UI-сессии и threadId, черновики и ссылки на вложения.
- [ ] Реализовать независимые состояния задач и очередь с лимитом 2.
- [ ] Проверки: события двух сессий не смешиваются; разрешение попадает в нужную вкладку; после перезапуска восстанавливается настоящий thread, а не только текст переписки.

### 6. Ветка и контекст
- [ ] Реализовать BranchService для директории каждой сессии и обновление состояния.
- [ ] Реализовать ContextUsageService на данных закреплённого протокола.
- [ ] Реализовать предупреждение >70%, красный индикатор >=90%, действие /compact и статус сжатия.
- [ ] Проверки порогов: 70%, 70.01%, 90%; неизвестное окно; накопительный расход не используется как заполненность; смена модели; автоматическое сжатие; ошибка ручного сжатия; смена ветки вне плагина; detached HEAD и отсутствие Git.
- [ ] Реальная проверка: /compact вызывает thread/compact/start, завершение определяется событиями, сообщение об успехе не показывается только по первому ответу RPC.

### 7. Проверить ресурсы и подготовить выпуск
- [ ] Измерить дополнительную память IDE и дочерних процессов на M2/8 ГБ: закрытая панель, один чат, два активных чата, длинная история; записать фактические результаты.
- [ ] Проверить восстановление после падения CLI, утечки при открытии/закрытии проекта, отсутствие секретов в логах.
- [ ] Выполнить unit/UI-проверки, сборку buildPlugin, Plugin Verifier для заявленных IDE и ручной сценарий в Android Studio.
- [ ] Подготовить README, лицензию, описание обработки данных, иконку, скриншоты и ZIP; выбрать самостоятельное публичное название.
- [ ] Подписание и публикация в Marketplace — отдельный этап после готовности проверяемой сборки.

## Особое внимание при проверке

1. События и разрешения нескольких threads никогда не смешиваются (этап 5).
2. Падение процесса не приводит к незаметной повторной отправке запроса (этап 2).
3. Заполненность контекста не путается с накопительным расходом и не выдумывается (этап 6).
4. Пути с пробелами/кириллицей и изображения корректно доходят до агента (этап 4).
5. Несколько чатов в одной директории показывают фактическую текущую ветку; отдельной изоляции не обещается (этапы 5–6).

## Критерий готовности первой версии

Пользователь устанавливает ZIP, подключает свой Codex, открывает панель, выбирает доступную модель, ведёт многострочный чат с файлами и изображениями, использует поддерживаемые команды и расширения, переключает именованные разговоры, восстанавливает историю, видит актуальную ветку и доступные данные контекста, при >70% получает предложение /compact и может выполнить сжатие. Агент выполняет обычные действия Codex с сохранением настроек разрешений. Режим обучения и отдельный diff-интерфейс отсутствуют.
